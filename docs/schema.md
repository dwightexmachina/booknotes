# Database schema

One SQLite file. Default path `~/.booknotes/books.db`, overridden by
`--db <path>` (highest precedence) or the `BOOKNOTES_DB` environment variable.
The file and its parent directory are created on first use. Connection
pragmas: `journal_mode = WAL`, `busy_timeout = 5000`, `foreign_keys = ON`.

## DDL

```sql
CREATE TABLE books (
  id           TEXT PRIMARY KEY,   -- UUID v4, generated by the CLI
  title        TEXT NOT NULL,
  author       TEXT,               -- plain text; no authors table yet
  publish_year INTEGER,
  edition      TEXT,
  created_at   TEXT NOT NULL,      -- UTC ISO-8601
  updated_at   TEXT NOT NULL
);

CREATE TABLE notes (
  id         TEXT PRIMARY KEY,     -- UUID v4, generated by the CLI
  book_id    TEXT NOT NULL REFERENCES books(id) ON DELETE CASCADE,
  section    TEXT NOT NULL DEFAULT '',  -- free text: "ch. 3-5", "pp. 112-140"
  body       TEXT NOT NULL,        -- the note itself
  position   INTEGER NOT NULL,     -- 1-based order within the book
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);

CREATE INDEX idx_notes_book ON notes(book_id, position);
```

## Ordering invariants

- `position` is 1-based and contiguous (`1..n`) within each book.
- New notes append at `max(position) + 1`.
- `note move` and `note delete` renumber the book's notes back to a
  contiguous `1..n` inside a transaction.
- Anything that reads notes must order by `position`.

## Word-count rule

Word counts are **derived, never stored**. The single canonical rule
(implemented once, in `cli/lib/src/repo.dart` `wordCount`, and mirrored by
nothing else — the UI gets counts from the API):

> Trim the body; if empty the count is 0; otherwise split on runs of
> whitespace (`/\s+/`) and count the pieces.

A book's aggregate word count is the sum over its notes. Any new code that
needs a word count must call the existing function or reproduce this exact
rule.

## Conventions

- Timestamps are UTC ISO-8601 strings (e.g. `2026-09-16T20:33:08.412891Z`),
  set by the CLI on insert and on every update.
- `author` and `edition` are nullable; the CLI's `book update` treats an
  empty-string argument as "clear this field" (stored as NULL).
- Deleting a book cascades to its notes (enforced by the FK, and the CLI
  prompts before doing it).
